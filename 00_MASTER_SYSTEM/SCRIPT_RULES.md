# Script Rules — Canonical

## Language
- Voice-over: natural German
- Internal creator explanation: Moroccan Darija / Arabic script when useful
- Short spoken sentences
- Easy for ElevenLabs to deliver naturally
- Avoid stiff written-German phrasing
- Final German script must not contain accidental Arabic / French / Darija fragments unless intentionally part of the concept

## Story
No rigid template, but a strong default is:
**Hook → curiosity gap → technical problem → explanation → proof → payoff**

This is a flexible storytelling framework, not a mandatory TikTok formula.

## Visual-first writing
Do not write a detail just because it is interesting.

A sentence belongs in the script only if it:
1. is true,
2. adds meaning,
3. can be shown realistically,
4. moves the story forward.

If the perfect footage is nearly impossible to obtain, rewrite the VO to a broader but still accurate claim.

## Density
Prefer one clear main idea over many side facts.
Delete facts that distract from the central mechanism.

## Duration
There is **no fixed canonical sweet spot**.

Current test ranges:
- 35–50s: growth-focused concise explainer
- 50–60s: medium-depth explainer
- 60s+: only when the story naturally supports it or when specifically targeting Creator Rewards eligibility

These are experiment buckets, not platform rules.

Shorter is better than padded.
Longer only if every section earns its time.

## Claims
Always distinguish:
- prototype
- production feature
- future application
- company claim
- measured test result
- peak vs sustained figure
- simplified engineering explanation vs exact operating value
- market / region differences

Never change the meaning of a metric for virality.

## Market consistency
For technical specs, prefer the official source matching the target audience / market when possible.

Example:
For German-facing BMW content, use BMW Deutschland / Global values relevant to Germany rather than mixing them with U.S. EPA figures.

## Presenter lines
Presenter lines should be short and purposeful.
The presenter does not need to speak every major section.
Use him for:
- hook
- pattern interrupt
- clarification
- reveal
- payoff

## Interaction / CTA
Prefer a CTA that emerges naturally from the topic.

Better:
- a real comparison question
- a choice between two next topics
- a technical opinion question
- a follow-up promise tied to the story

Avoid generic “Folge für mehr” as the default.

The CTA must not distort the story just to force comments.

## Final pass
Remove:
- repeated ideas
- generic filler
- details with no footage
- long explanations that can be shown visually
- unnecessary conclusions
- ambiguous “guess” questions
