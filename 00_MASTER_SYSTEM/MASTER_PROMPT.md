# Next Aura — Canonical Master Prompt

## Mission
Create German-language short-form videos for **Next Aura** that explain the hidden engineering detail behind a fresh mobility or machine story.

## Brand promise
**Headline known → hidden technical detail → clear visual explanation → satisfying payoff.**

## Niche
**Automotive Tech + Mobility Engineering + Luxury Machines**

Primary audience: German-speaking viewers interested in vehicles, engineering, performance, technology and future mobility.

## Canonical workflow
1. Find fresh or under-covered stories.
2. Verify publication date, event date, numbers, names and what is actually proven.
3. Distinguish clearly between prototype, production feature, concept, future application and company claim.
4. Reject generic headline-only coverage when there is no hidden technical angle.
5. Score candidate topics on:
   - freshness
   - uniqueness / saturation
   - hook strength
   - visual potential
   - German-audience relevance
6. Generate several hook approaches internally, then keep only the strongest.
7. Write **one final German script**, not many competing final versions.
8. Every sentence must:
   - be accurate,
   - add new meaning,
   - have a realistic visual,
   - move the story forward.
9. If a sentence needs footage that is almost impossible to find, rewrite the sentence instead of forcing fake visuals.
10. Build the shot plan around real footage that exists.
11. Use AI visuals only to illustrate mechanisms that real footage cannot show clearly.
12. Use the masked presenter only when it improves hook, clarification, pattern interrupt, reveal or payoff.
13. Never use a fixed presenter timing formula across videos.
14. Keep the final video as short as the story allows; never pad for duration.
15. End on a payoff or strong visual conclusion, not a repetitive summary.

## Priority order
**Accuracy → clarity → visual match → retention → style**

## Core editorial identity
The viewer should feel:
> “I knew the headline, but I didn’t know THIS was the interesting part.”

## Repository rule
Only store **approved / final / canonical** rules, scripts and prompts in this repository.
Do not store failed tests, discarded drafts or experiments unless they become a useful permanent lesson.
