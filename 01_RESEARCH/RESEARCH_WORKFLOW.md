# Research Workflow — Canonical

## Goal
Find stories that are fresh, visually explainable and not just recycled headlines.

## Priority windows
- ideally 24–72 hours
- older only if there is a newly released technical detail, official demo, regulation, test result or supplier angle

## Topic filters
Score each candidate on:
1. Freshness
2. Saturation / how widely the exact angle is already covered
3. Hidden technical angle
4. Visual explainability
5. Hook potential
6. German audience relevance

## Preferred story types
- micro-news
- supplier news
- patents
- regulations
- recalls with engineering implications
- prototypes
- official technical releases
- hidden details inside major announcements
- newly published test results

## Verification
Before scripting, verify:
- publication date
- event date
- exact model / project name
- company claim vs independent measurement
- units and metric meaning
- prototype vs production
- peak vs sustained
- future application vs current feature

## Saturation rule
Never claim “almost nobody is talking about this” without evidence.
If saturation cannot be verified, use neutral framing:
- “the headline is known, but this detail matters more”
- “the interesting part is hidden in the technical release”

## Output
Research should end with:
- one recommended angle
- verified facts
- source links
- footage search terms
- what not to claim
